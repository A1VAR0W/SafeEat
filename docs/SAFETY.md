# Evidence model and audit boundaries

`CONTAINS_GLUTEN` takes precedence over `MAY_CONTAIN_TRACES`, then a non-contradictory explicit declaration, then `UNKNOWN`. Oats without a gluten-free declaration remain unknown. The input provenance and literal matched evidence are returned alongside reasons and engine version. Confidence is evidence confidence, not a probability that eating the product is safe.

Spanish and English are the supported languages. Unicode compatibility normalization, accent folding, case, punctuation and phrase context are explicit. The engine is a conservative rules system, not a medical classifier. It cannot detect a missing OCR line, verify a manufacturer's certification, determine a laboratory ppm measurement or validate community data. Reviewed OCR claims retain limited confidence. Never replace label inspection with this result.

Since engine 1.2.0 (rules 2026.11.13) an analysis layer classifies every ingredient with a versioned rule catalog (Regulation (EU) 1169/2011 Annex II, Implementing Regulation (EU) 828/2014, AESAN, FACE, Coeliac UK) and states the case in `assessment.finding`: declared gluten, declared traces, ambiguous ingredient, no gluten ingredients identified, gluten-free claim, insufficient or contradictory information. Legal exemptions (wheat glucose syrups, dextrose, maltodextrins, distillates) are not gluten evidence but never make a product green; naturally gluten-free ingredients never make it safe either. The on-server AI only classifies ingredients the catalog does not know, answers in a closed JSON schema, and never changes the status: a suspicion is shown as unconfirmed, in neutral colours. Details, evaluation and limits: [GLUTEN-ANALYSIS.md](GLUTEN-ANALYSIS.md).

Since engine 1.2.1, texts of the same product (other languages, a machine translation) are reconciled by provenance: a translation of a readable original never proves gluten nor erases the original, while any other list of the record can block a "sin gluten". A list the item parser had to truncate never gets the reassuring "no gluten ingredients identified" text. Every assessment states its provenance (manufacturer, external declaration, community, automatic, insufficient): a "sin gluten" recorded by the community is shown as an unverified declaration, never green. How current the data is (`freshness`) is shown separately from the status; old cached data is never presented as a current confirmation, and a network failure never turns anything into a warning. The "gluten-free" search filter uses food evidence only; personal verdicts have their own filter and are flagged for review when allergens, traces or declarations change.

Community gluten reports are stored separately from the rules-engine assessment. A single user's statement never changes the underlying assessment or certifies a product. Conflicting reports are shown as conflicting, and a reported risk can suppress a favorable display label. Restaurant dietary tags and user reports describe options but do not verify preparation or cross-contact controls. Each restaurant label states its source (OpenStreetMap tag, SafeEat users, users including a trusted account, or insufficient/contradictory); none is presented as an inspection. Where the restaurant catalog was not imported the map says it has no data, which is not the same as no restaurants.

SafeEat Quality Score v1 is a transparent, unvalidated heuristic, independent of gluten. Six required numeric inputs per 100 g/ml: energy, sugar, saturated fat, salt, fibre and protein. Invalid, absent or implausibly inconsistent values produce no score. The score is rounded to multiples of five to avoid false precision. Nutri-Score from OFF is shown separately.

Regression tests cover positive and negated claims, contradictory evidence, traces, oats, Unicode, invalid nutrients and provider normalization. Security integration tests cover hashed credentials, user isolation, rotating-token replay, logout, account deletion and public data minimization. Physical-device OCR/camera, nutritional validation and manufacturer verification remain distinct from software tests.
