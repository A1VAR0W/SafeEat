# SafeEat 1.0.11 — panel de administración

La versión 1.0.11 (Android versionCode 87) está preparada para publicación. El panel requiere que se despliegue también la API actualizada.

La migración `009_admin_moderation.sql` se ha aplicado directamente a la BBDD de producción, tras una copia de seguridad. Se ha creado el rol `ADMIN`, asignado a la cuenta solicitada y registrado ese alta en la auditoría. La migración está registrada en `schema_migrations`, de modo que el siguiente despliegue la omite. Las nuevas columnas son compatibles con la API 1.0.10 que sigue desplegada; sus endpoints de administración todavía no existen.

El panel se abre desde «Tu espacio → Administración» para administradores. Incluye búsqueda de usuarios por nombre o correo, gestión de la autorización de celíacos, revisión de productos y restaurantes, estados activo/revocado y acceso a la ficha. Los nombres se pueden buscar sin tildes. Las decisiones de moderación se toman desde una pantalla con la aportación completa y un motivo administrativo. Las acciones se confirman y su resultado se comunica en el panel. Se reutilizan las tarjetas, paleta, tipografía, controles accesibles y desplazamiento de formularios existentes.

Cada modificación exige una sesión vigente y ADMIN en el servidor. La sesión y el rol se vuelven a comprobar dentro de la transacción. El panel únicamente gestiona `authorized_celiac`; no permite elevar cuentas a ADMIN. Los cambios quedan en `admin_audit_log`. Las revisiones se revocan sin borrar su contenido, con autor de la decisión, fecha y motivo. No cuentan en las fichas, herencia de cadenas, verificaciones ni filtros del catálogo, y el autor no puede republicarlas para saltarse la decisión. Restaurarlas requiere una nueva decisión administrativa; las confirmaciones manuales anteriores se invalidan. Una revisión modificada desde que se abrió se rechaza con conflicto para evitar moderar un texto distinto.

Solo las cuentas con `authorized_celiac` pueden enviar motivos vacíos, omitidos o breves, en productos, restaurantes y la revisión inicial de un nuevo restaurante. Se mantiene el límite de 500 caracteres. Para el resto siguen siendo necesarios al menos diez caracteres. ADMIN por sí solo no implica esa autorización. El rol se consulta en BBDD; no se confía en permisos enviados por el cliente. Una revisión sin texto se muestra como «Sin motivo añadido», sin inventar una explicación.

Las consultas administrativas no se persisten en disco y se eliminan de la caché al cerrar sesión. La moderación invalida las fichas y resultados afectados; la selección del mapa consulta la ficha actual y el historial de un producto moderado se actualiza con los datos del servidor.

Validación realizada sin build: tipos, lint, formato, 146 pruebas unitarias y 44 de integración con PostgreSQL/PostGIS aislado. Incluye protección del panel, concesión y retirada de autorizaciones, comprobación de permisos vigentes, auditoría, revocación/restauración, conflictos de revisión, bloqueo de republicación y motivos opcionales solo para autorizados. El smoke de la API de producción 1.0.10 pasó tras aplicar la migración. La UI queda pendiente de comprobación en dispositivo con esta compilación.
